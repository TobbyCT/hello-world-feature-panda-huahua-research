# 仿生熊猫机器人 Demo PRD

版本：V1.2  
日期：2026-06-10  
状态：Demo PoC 评审版  
适用阶段：前期演示样机 / 结构可行性验证 / 客户与投资展示验证

## 1. 文档目的

本 PRD 用于定义“熊猫花花仿生机器人 Demo 样机”的最小演示范围。

当前阶段不是完整产品定义，也不是量产规格书。本文只回答三个问题：

1. 这个 Demo 要给谁看？
2. 现场 30 秒内要演示出什么效果？
3. 做完样机后，如何判断是否值得进入下一阶段？

本版本根据评审意见进行收敛：减少过多功能定义，聚焦“外观看起来像熊猫、摸头后有回应、头眼前肢能联动、核心结构能装进去”。

## 2. 产品阶段定义

本期产品定位为 Demo PoC 样机。

它的目标不是做一只完整可售卖的仿生熊猫机器人，而是验证一条最小展示闭环：

> 在可展示的熊猫外形中，证明头部、眼睛、触摸、语音和前肢动作能够形成“像在回应人”的演示效果。

### 2.1 本期优先服务对象

| 对象 | 本期是否服务 | 关注点 |
|---|---|---|
| 客户 / 投资人 | 是 | 30 秒内能否感受到熊猫有生命感 |
| 内部研发团队 | 是 | 头眼机构、主板、线束、前肢机构是否能集成 |
| 宣传拍摄团队 | 是 | 动作是否可控，是否能拍出眼睛和互动亮点 |
| 儿童 / 游客长期互动 | 暂不作为本期目标 | 不做长时间开放触摸和运营验证 |
| 家庭消费用户 | 本期不服务 | 不考虑抱起、耐摔、认证、长期陪伴 |

## 3. Demo 核心目标

本期 Demo 只验证四件事：

| 目标 | 说明 | 成功表现 |
|---|---|---|
| 熊猫识别度 | 外观第一眼能识别为熊猫花花方向 | 头脸、黑眼圈、耳朵、毛绒轮廓基本成立 |
| 生命感 | 不是静态玩偶，而是会看、会眨、会回应 | 待机有轻微动作，摸头后有明确反馈 |
| 结构可行性 | 眼部机构、主板、驱动、线束能装进样机 | 不因内部空间不足导致头部比例完全失控 |
| 演示可复现 | 现场能按固定脚本稳定演示 | 30 秒主流程可重复演示 3-5 次 |

## 4. 30 秒主演示闭环

本期 PRD 以演示链路为核心，而不是以功能数量为核心。

### 4.1 标准演示流程

| 时间 | 阶段 | 画面 / 行为 | 机器人反馈 |
|---|---|---|---|
| 0-5 秒 | 待机 | 熊猫坐在桌面或展台上 | 随机眨眼，头部轻微巡视 |
| 5-10 秒 | 吸引注意 | 演示者靠近或触发演示 | 头部回正，看向前方 |
| 10-18 秒 | 摸头互动 | 演示者摸头 | 眨眼 + 点头 + 播放一句短语音 |
| 18-25 秒 | 展示动作 | 演示者触发动作脚本 | 前肢轻微抬起并挥手 |
| 25-30 秒 | 回到待机 | 演示结束 | 头部回正，继续轻微眨眼 |

### 4.2 核心互动反馈

摸头后的反馈必须固定成一条清晰链路：

> 摸头 -> 眨眼 -> 点头 / 轻微转头 -> 短语音

原因：只做“眨眼、点头、语音任选其一”会让用户感受不到它在回应自己。本期 Demo 要优先保证这条链路成立。

## 5. 本期范围

### 5.1 必须实现

| 模块 | 本期要求 | 备注 |
|---|---|---|
| 外观 | 具备熊猫花花方向的基本识别度 | 比例可调，不锁最终造型 |
| 头部运动 | 支持左右转头、上下点头 | 角度为调试目标，不作为量产指标 |
| 眼部动作 | 支持眨眼 | 优先保证机构可动和可装配 |
| 头部触摸 | 只保留头部触摸区域 | 摸头后触发核心回应链路 |
| 语音播放 | 支持预置语音播放 | 本期是播放语音，不是听懂对话 |
| 前肢动作 | 单侧或双侧前肢做轻挥动作 | 作为展示增强，不扩展复杂动作 |
| 内部集成 | 眼部结构、主板、驱动和线束有安装空间 | 本期最重要的结构验证之一 |
| 一键演示 | 支持隐藏按键、遥控或上位机触发主演示 | 便于客户展示和拍摄 |

### 5.2 本期不做

| 不做内容 | 说明 |
|---|---|
| 下肢主动动作 | 本期下肢保持静态，不做摆动、爬行、行走 |
| 抱起体验 | 不考虑用户抱起、携带、跌落和耐摔 |
| 多区域触摸 | 不做背部、腹部、前肢触摸 |
| AI 问答 | 不作为本期验收项，可在宣传中作为未来方向 |
| 语音识别 / 唤醒词 | 本期只做预置语音播放和事件触发 |
| 完整连续运行测试 | 不做 2 小时连续运行验收 |
| 完整安全认证 | 不做儿童玩具认证、安规认证、量产安全测试 |
| 眼睛最终材质定型 | 反光、高光、虹膜材质暂不作为硬性验收 |
| 量产结构定型 | 本期只验证方向，不锁量产开模方案 |

## 6. 功能需求

### 6.1 外观与比例

| 项目 | 要求 |
|---|---|
| 外观方向 | 熊猫花花风格，突出圆脸、黑眼圈、黑耳朵、毛绒感 |
| 尺寸方向 | 优先桌面级或中小型展台样机 |
| 比例原则 | 允许为了容纳眼部机构和主板适当放大头部 |
| 评审方式 | 至少输出 2 个比例方案：结构优先版、外观协调版 |

比例不是本期硬锁项。评审时重点看“能不能装下”和“会不会因为装机构而不像熊猫”。

### 6.2 头部运动

| 项目 | 要求 |
|---|---|
| 自由度 | 左右转头 + 上下点头 |
| 动作风格 | 慢速、柔和，避免突然甩头 |
| 触发方式 | 待机随机、摸头触发、一键演示触发 |
| 演示目标 | 让用户感觉熊猫在看向自己、回应自己 |

建议调试目标：左右转头约 +-30 度，上下点头约 +-15 度。实际角度以结构可行性和外观效果为准。

### 6.3 眼部动作与结构

| 项目 | 要求 |
|---|---|
| 眨眼 | 支持自动眨眼和摸头触发眨眼 |
| 默认节奏 | 待机状态可随机眨眼 |
| 眼部结构 | 眼球、眼睑、驱动件、线束能装入头部 |
| 眼神要求 | 默认眼神不能显得惊悚、呆滞或明显穿帮 |
| 材质处理 | 本期不强制最终高光和反光材质 |

眼睛是本期核心亮点。即使材质还不是最终版，也必须保证视频中能看出“眼睛会动、会眨、像在回应”。

### 6.4 头部触摸

| 项目 | 要求 |
|---|---|
| 触摸区域 | 仅头部 |
| 反馈链路 | 眨眼 + 点头 / 轻转头 + 短语音 |
| 响应目标 | 摸头后 500ms 内开始出现可感知反馈 |
| 连续触摸 | 设置 1-2 秒冷却，避免重复触发导致动作冲突 |

### 6.5 语音播放

| 项目 | 要求 |
|---|---|
| 本期定位 | 预置语音播放 |
| 语音数量 | Demo 阶段建议 5-8 条即可 |
| 语音类型 | 欢迎、摸头回应、卖萌、科普、待机 |
| 触发方式 | 摸头触发、一键演示触发、待机触发 |
| 明确边界 | 本期不承诺语音识别和 AI 问答 |

示例语音：

| 场景 | 示例 |
|---|---|
| 欢迎 | “你好呀，欢迎来看我。” |
| 摸头 | “嘿嘿，好舒服。” |
| 卖萌 | “我有一点点困啦。” |
| 科普 | “我是大熊猫，最喜欢吃竹子。” |
| 引导 | “你可以轻轻摸摸我的头。” |

### 6.6 前肢动作

| 项目 | 要求 |
|---|---|
| 动作范围 | 前肢轻微抬起、轻挥、放下 |
| 动作数量 | 本期只需要 1 个完整挥手动作 |
| 联动方式 | 可与语音或摸头后的演示脚本联动 |
| 边界 | 不做抱竹子、不做复杂四肢联动 |

前肢动作是展示增强项，不应影响头部、眼部和摸头回应这条主链路。

## 7. 简化状态机

| 状态 | 触发条件 | 行为 | 退出条件 |
|---|---|---|---|
| 待机 | 开机后无操作 | 随机眨眼，轻微头动 | 摸头或一键演示 |
| 摸头回应 | 头部触摸 | 眨眼、点头、播放短语音 | 动作完成 |
| 说话中 | 播放语音 | 可轻微眨眼，避免动作冲突 | 语音结束 |
| 挥手展示 | 一键演示触发 | 前肢轻挥 | 动作完成 |
| 冷却 | 连续触摸后 | 暂停重复触发 | 1-2 秒后回待机 |

## 8. Demo 通过标准

本期不做复杂验收，采用“演示是否成立”的方式判断。

| 维度 | 通过标准 |
|---|---|
| 30 秒闭环 | 待机、摸头回应、语音、挥手、回待机流程完整 |
| 互动感 | 用户摸头后能明确感受到熊猫在回应 |
| 熊猫识别度 | 观看者能第一眼识别为熊猫方向 |
| 眼部亮点 | 视频中能明显看到眨眼或眼部动作 |
| 结构可行 | 眼部机构、主板、驱动、线束能完成基本装配 |
| 演示复现 | 主演示流程可连续重复 3-5 次 |
| 拍摄可用 | 能拍出 15-30 秒宣传素材中的核心镜头 |

## 9. 演示边界与基础约束

用户已明确本期暂不考虑完整安全性能问题，因此本文不引入量产安全指标。但为了保证现场 Demo 不出明显问题，保留最低演示约束：

| 项目 | 最低要求 |
|---|---|
| 用户触摸区域 | 只允许摸头，不开放其他区域 |
| 外露线束 | 面向客户演示时不应有可触碰外露线束 |
| 前肢动作 | 速度柔和，不突然甩动 |
| 机构干涉 | 毛绒、眼睑、线束不得明显卡住动作 |
| 停止方式 | 演示人员应能快速断电或停止动作 |

这些不是量产安全验收，只是 Demo 现场的基本展示底线。

## 10. Go / No-Go 判断

Demo 完成后，用以下问题判断是否进入下一阶段：

| 判断问题 | Go 标准 | 返工 / 暂停条件 |
|---|---|---|
| 结构路线是否可行 | 眼部、主板、线束、前肢能集成 | 头部必须放大到明显不像熊猫 |
| 互动体验是否成立 | 摸头后用户能感到它在回应 | 用户只觉得是机械玩具在动 |
| 展示是否有说服力 | 30 秒流程可稳定演示并可拍摄 | 经常卡滞、误触发或需要人工补救 |
| 眼部亮点是否突出 | 眼睛动作在现场和视频中可见 | 眼部动作太弱或被毛绒遮挡 |
| 下一步是否清晰 | 能明确下一阶段要优化结构、外观或交互 | 核心技术路线仍无法判断 |

## 11. 评审问题响应表

| 评审问题 | 本版处理 |
|---|---|
| 产品定位不够聚焦 | 明确为 Demo PoC，不定义完整产品 |
| 目标对象不清楚 | 聚焦客户 / 投资展示、内部研发和宣传拍摄 |
| 生命感没有指标 | 改为 30 秒闭环、摸头回应感、眼部可见性 |
| P0 范围偏大 | 压缩为头眼触摸语音结构主链路，前肢只保留一个展示动作 |
| 交互闭环缺失 | 固定摸头后的“眨眼 + 点头 + 短语音”链路 |
| 语音边界模糊 | 明确本期是预置语音播放，不是 AI 对话 |
| 样机边界不足 | 增加桌面级、比例可调、结构空间优先 |
| 安全底线争议 | 不做完整安全测试，仅保留 Demo 现场最低约束 |
| Go / No-Go 缺失 | 增加阶段决策标准 |

## 12. 最终表述

熊猫花花仿生机器人 Demo 样机的本期目标，是在一个可展示的熊猫外形中，验证头部运动、眼部眨眼、头部触摸反馈、预置语音播放和前肢轻挥动作能否形成 30 秒内可感知的“生命感互动”。

本期成功不以功能数量为标准，而以“结构装得下、摸头有回应、眼睛有亮点、演示可复现、视频能拍出来”为标准。下肢动作、抱起体验、多区域触摸、AI 问答、长期稳定性、完整安全认证和量产结构定型均不纳入本期范围。

一句话总结：

> 这不是一版完整机器人产品 PRD，而是一版用于证明“熊猫花花 Demo 值不值得继续做下去”的最小演示 PRD。
